Question 2 →  Explain the difference between LIST, TUPLE, SET & DICTIONARY

A List is an ordered, mutable collection that allows duplicate values. It is used when the data needs to be modified dynamically.

fruits = ["Apple", "Banana", "Orange"]

fruits.append("Mango")
fruits[1] = "Grapes"
fruits.remove("Apple")

A Tuple is an ordered, immutable collection that allows duplicate values. It is commonly used for fixed data that should not change.

browser = ("Chrome", "120")

A set is unordered, mutable collection that don't allows duplicate values. Set has unique values only.

A DICTIONARY is an ordered, mutable collection that allows duplicate values ( Key should be unique but values can be duplicate). It is commonly used for data structures in automation.

login_data = {
    "username": "admin",
    "password": "Admin123"
}

    "status": "SUCCESS",
    "code": 200

Question 3 → "What happens internally when Selenium executes this line?" driver.find_element(By.ID, "username").click() 

Senior QA Automation Engineer , I should explain how it works internally, not like 4 yrs of tester. 

Step → 1, When Python executes this method, nothing happened in the browser yet.
Step → 2, For executing this method, we need a selenium client library that sends requests to the browser. The request follows the W3C webdriver protocol.
Step → 3, When Selenium sends the request directly to the browser , it can’t send it directly. For that we have to add, chromedriver for chrome, firefox driver for mozilla, Gheckdriver for edge.
Step → 4,  Browser driver receives the HTTP request, translates it to the commands that chrome browser understands.  Python → ChromeDriver → ChromeBrowser.
Step → 5, Browser searches the DOM, if it finds the element.
Step → 6, Element ID is returned, Chromedriver sends back the reference to selenium, selenium stores the reference.
Step → 7, Now, selenium sends another request, .CLICK() which means, click the element.

→ Why do we need ChromeDriver? 

"Browsers don't understand Selenium commands directly. ChromeDriver acts as a bridge between the Selenium client library and the Chrome browser by translating WebDriver protocol commands into browser-specific actions."

Question 2

Explain the Selenium Architecture without looking at your notes.

⭐ Senior-Level Interview Answer

"When Selenium executes the statement driver.find_element(By.ID, 'username').click(), the first step is that the Selenium Python client library receives the request from the Python script.

The Selenium client then creates an HTTP request following the W3C WebDriver Protocol and sends it to ChromeDriver.

ChromeDriver acts as a bridge between Selenium and the Chrome browser. It translates the WebDriver command into browser-specific instructions that Chrome understands.

Chrome searches the DOM for the element whose ID is username. If the element is found, Chrome returns an element reference back through ChromeDriver to the Selenium client.

When the .click() method is executed, Selenium sends another WebDriver command to ChromeDriver, which again forwards it to Chrome. Chrome then performs the click action on that element."

But a Senior Engineer should also explain what happens if the element is NOT found.

For example:

"If the element is not found, Selenium waits according to the configured wait strategy. If no matching element is found within the timeout period, it throws a NoSuchElementException."

Follow Up Question --> 

Why don't we use a List for everything? Why do Python developers still use Tuples, Sets, and Dictionaries?

"Each Python collection serves a different purpose. I use a List when I need an ordered collection that may change during execution, such as storing multiple WebElements or test data. I use a Tuple for fixed configuration values because it's immutable. A Set is useful when uniqueness is important, for example validating that a menu doesn't contain duplicate items. A Dictionary is my preferred choice for configuration data, API responses, and test data because key-value access is fast and expressive. Choosing the right collection improves readability, maintainability, and performance where appropriate."
